# Switchboard · 总台制

**一套让多个 AI 编码代理长期协同干活的组织方式。不是框架,不用安装任何东西 —— 它的全部内容是几条不许破的规矩,以及把状态从对话里搬到磁盘上这一个动作。**

> **本仓以英文为主语言**,英文版见 [README.md](README.md)。中文版内容与英文版一致,以英文版为准。

---

## 这套东西解决的问题

代理最容易犯的错**不是写错代码**,是**如实报告一件它以为发生了的事**。

它会说"改完了,测试都过了" —— 而它确实这么认为。可能测试根本没跑到那一行;可能它加的钉子(测试断言)本身是空的;可能它改的是另一个文件。**在纯对话式的协作里,你几乎没有便宜的办法发现这件事。**

再加上三个现实:

- 对话上下文会被压缩、会中断、会重启。**只存在于对话里的状态,等于随时会消失。**
- 让同一个代理审自己的作业,它会给自己打高分。
- 一个代理长期握着全部工具,一次失误的波及面等于整个仓库。

**总台制就是针对这四件事的。**

## 原本会出什么问题,这套架构怎么处理

每一行都是「一个代理、一段对话、单干」的真实失效。**最后一列最重要:每一条主张都附一个能证伪它的方法。** 无法被证伪的 README 是宣传册。

| 你实际会遇到的 | 为什么会这样 | 这套架构怎么做 | 怎么验证它真的有用 |
|---|---|---|---|
| **「改完了,测试都过了」—— 其实没有** | 关于这件工作,唯一的说法来自它自己 | 验收只认实物:改动、检查输出、**确切的失败信息** | 把功能整个删掉再跑一遍。**还是绿的?那道保护是空的** |
| **几周之内没人发现** | 写代码的那个上下文,同时在审这段代码 | 审查方**零写权限**,且**与作者没有通道** | 要它拿出一把**红了的刀**。没有刀,就不算审过 |
| **理由没了** | 压缩和重启留下结论,留不下原因 | 账本记录**当时的**理由,不只是结论 | 挑一个一个月前的决定,试着复原当初为什么这么定 |
| **一次崩溃赔掉整段工作** | 一个进程同时装着工作和它的状态 | 一次性班次;实物**持续落盘** | 半路把班次杀掉。对着磁盘盘一遍 —— 真正丢的有多少? |
| **一步错,处处受影响** | 所有工具一直都在手上 | 权限**按单发放** | 看那条启动命令:它列的是这一单要用的工具,还是全部? |
| **人要么全盲,要么累死** | 要么每次调用都批,要么什么都不批 | 人**只在不可逆的那一步出现** | 数一数一天被打断几次,每次是为了什么 |


## 五条不许破的规矩

### 1. 验收只认实物

代理说"做完了"不算数。只认**改动本身、文件、检查结果、能打开的页面**。

> **为什么:**汇报是线索,不是证据。代理不会故意骗你 —— 它只是会真诚地报告一件没发生的事。

### 2. 审查必须结构性独立

审查方**对被审对象没有写权限**,并且**不与作者直接通信** —— 意见由枢纽转写成工单发给作者。

> **为什么:**"要客观"这类嘱咐对代理作用有限。把写权限拿掉、把通道切断,它没有别的选择,只能去读实物。**独立不能靠嘱咐,只能靠结构。**

### 3. 状态写在磁盘上

工单、回信、决定、留痕,全部是文件。**对话是驾驶座,不是数据库。**

> **为什么:**压缩、崩溃、重启是常态,不是意外。写在文件里的东西,换一个人、换一台机器都能接着干。

### 4. 班次一次性,权限按单发

每次开工都是一个**全新进程**,没有上一次的记忆,靠工单 + 磁盘上的实物工作。工具权限**按这一单的需要单独给**。

> **为什么:**没有记忆就没有漂移;权限按单给,一次失误的波及面被这一单框住。

### 5. 不可逆的那一下,人来按

合并、上线、对外发布 —— 代理做到"可以按了"为止,**按的动作留给人**。

> **为什么:**不是不信任。是把人放在**信息最全、代价最大**的那一个点上,而不是让人去审每一次改动。

## 和传统 harness 的差别

这里说的 harness,指"一个代理 + 一堆工具"的常见运行外壳:主代理在**一个进程、一个上下文**里干活,需要时派生子代理,子代理干完交回**一段文字总结**。

差别不在"有没有多个代理",而在 **状态放在哪里、谁来验、谁能改什么**。

| 维度 | 传统 harness | 总台制 |
|---|---|---|
| 状态存放 | 对话上下文。压缩或重启即失忆 | **磁盘上的文件** |
| 交付物 | 一段文字总结,真假不可查 | **实物**,第三方能自己看 |
| 谁来验 | 同一个代理自评 | **只读的审查方 + 枢纽自己再动手验一遍** |
| 审查独立性 | 靠提示词嘱咐"要客观" | **靠结构**:无写权限,且与作者不直连 |
| 失败半径 | 进程死 = 整段工作连同状态一起没 | **只丢那一个班次**,对着实物盘点续跑 |
| 权限 | 一个代理长期握着全部工具 | **按单发放** |
| 并行 | 受同一个上下文窗口牵制 | **不同工位真并行**,各有各的窗口 |
| 人的位置 | 要么全程盯,要么完全放手 | **只在不可逆的那一下出现** |

## 优势落在哪里

1. **长任务不再受上下文长度限制。** 枢纽只保留**决定和判据**,细节留在文件里。上下文变成可回收的资源,而不是会耗尽的仓库。
2. **中断变成小事。** 损失上限是**那一个班次**。恢复动作是固定的:对着实物盘一遍,已完成的不重做,没做的续上。
3. **质量来自结构,不来自嘱咐。** 见规矩 2。
4. **出了事能查。** 每一次派单、验收、决定连同**当时的理由**都在账本里。纯对话协作最缺的就是这个 —— **结论会留下,理由不会。**
5. **人的注意力花在刀刃上。** 人看到的是一句话结论加一句"我是怎么核的",而不是一堆过程。

## 诚实的代价

不写这一节,这份说明就是广告。

- **慢。** 信箱一来一回、审查一轮、复核一轮。**改一个错别字走这套流程是荒谬的。**
- **枢纽是瓶颈,也是单点。** 它记错账、漏派单、转述时把别人的理由说歪,整条链就跟着歪。**这套制度里最需要纪律的是枢纽自己。**
- **重复读取。** 每个班次都要重新读一遍背景。这是"无记忆"换来的代价。
- **记账是硬活。** 派单和记账必须是同一个动作。**漏记一次,状态显示就在撒谎**,而所有人都照着它做判断。

---

## 什么时候不该用

看两件事:**这件事出错的代价有多大,以及它会不会跨越一次中断。**

一次性小改动、探索性尝试、随手问个问题 —— **直接做,别开流程。**

**规矩的价值来自它被守住,不是来自它被写下来。** 用在配不上它的地方,守不住是必然的;而守不住的规矩比没有规矩更糟 —— 因为所有人都以为它还在。

## 怎么上手

```bash
git clone https://github.com/tommyy1708/on-chain-agents-method.git coordination
cd coordination && cp ledger.example.json ledger.json
```

**→ [SETUP.zh.md](SETUP.zh.md) —— 目录怎么摆、第一单怎么完整跑一遍、以及别这么干的几件事。**

在别的事情之前,先把目录摆对:**你的代码库、每个工位一份工作副本、以及一个不属于任何工位的协调目录。** 信箱和账本一旦落在某个工位的地盘里,**那个工位就能改自己的成绩单。**

```
PROTOCOL.zh.md         协议:信箱怎么用、消息什么格式、谁能写谁只能读
ACCEPTANCE.zh.md       验收:什么算实物、刀验(mutation)怎么做
SETUP.zh.md            安装与第一次运行
BENCHMARK.zh.md        评测设计(尚未运行,见文件内说明)
example/               一份工单走完整流程(英文,先读 04-reply-review.md)
templates/*.zh.md      工单 / 审查工单 / 回信 三个模板
mailbox/               信箱目录骨架
ledger.example.json    账本结构示例
scripts/dispatch.sh    派一个班次**并且**记账 —— 两件事拆不开
scripts/accept.sh      收一个班次**并且**记下怎么核的(--note 必填)
scripts/statusline.sh  读账本,把全员状态显示在命令行底部
```

**环境要求**:bash、python3、git,以及一个能**一次性、非交互**运行并可限制工具的 agent CLI —— 例如 `claude -p "<prompt>" --allowedTools "…"`。

**别一上来就加审查工位。** 前两条规矩(实物验收 + 状态落盘)能解决大部分问题,而且不花钱。独立审查是第二步。
